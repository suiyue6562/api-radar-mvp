### 1.2 功能层

#### P0：API Key 兼容性测试
**为什么**：用户充值了 DeepSeek 渠道，结果发现不兼容 OpenAI 协议。
**做什么**：
- 用户粘贴 base_url + API key + 测试模型名
- 站点代理发一个最小请求（10 tokens）
- 返回：成功 / 失败 + 错误码 + 是否兼容 OpenAI/Anthropic 协议
- **不存储 API key**（只在内存中传递，写入 localStorage 加密）
- 失败时给出**替代渠道建议**（如不兼容 OpenAI → 推荐 OpenAI/Anthropic 兼容的渠道）

#### P0：价格计算器补全
v1.1 已有输入输出 + 缓存价（部分实现）。v2.0 补：
- 长上下文加价（>32K / >128K / >1M 分段加价）
- 阶梯量折扣（部分渠道的 enterprise tier）
- 输出峰值速率限制（影响并发成本）
- 实际月成本估算（含缓存命中预估：用户输入典型 cache_hit_ratio）

#### P0：速报订阅（v2 形态）
- **邮件订阅**：用户填邮箱，每周二/五 09:00 发"上周价格变动+服务事件+新模型"汇总
- **Telegram bot**（可选）：@api_youxuan_bot，关注 `/watch` 列表
- 实现：订阅数据存 Cloudflare D1（免费 SQLite），用 Cloudflare Workers 触发邮件
- **不用第三方服务**（避免成本），用 Resend 邮件 API（每月 100 封免费）

#### P1：其他页面赛博朋克改版
- providers.html（v1 已有，做成首页风格一致）
- models.html（v1 已有，UI 一致化）
- events.html（v1 已有，UI 一致化）
- compare.html（v1 已有，UI 一致化）
- watch.html（v1 已有，UI 一致化）
- method.html、provider.html、model.html（同样改版）
- **全部用统一的赛博朋克 design tokens**（style.css 抽到 base.css，所有页面引入）

## 2. 不做的事（v2.0 明确砍掉）

| 不做 | 原因 |
|---|---|
| 价格预测 | 数据量不够，预测会变成玄学 |
| 实测报告（人工跑 benchmark） | 人力成本高，v3 再考虑 |
| 模型评分 / 用户评论 | 易被刷分，破坏可信度 |
| 企业询价 / 合同采购 | 独立项目，不是 v2.0 范围 |
| 订阅制（Pro 会员） | 没有足够差异化的功能 |
| 移动端 App | Web 优先，App 后置 |
| 多语言（英文版） | 国内开发者优先，英文版 v3 |

## 5. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 调研瘫痪 | 高 | 死 | **本 PRD 只 2 页**，不再追加 |
| API key 测试滥用（用站点代理发请求做攻击） | 中 | 高 | 限流 + 失败立即返回 + 不存储 key |
| 邮件订阅被滥用（订阅垃圾地址） | 中 | 中 | Cloudflare Turnstile 验证 + 邮箱格式校验 |
| 数据深度补全速度慢 | 中 | 中 | 优先补**有决策影响的字段**（缓存价、长上下文加价），次要字段可空 |
| 5 个用户试用反馈负面 | 低 | 中 | 把反馈分成"必须有 / 可改进 / 个人偏好"三类，只改前两类 |
