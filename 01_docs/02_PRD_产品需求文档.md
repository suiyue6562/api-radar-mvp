## 1. 产品概述

### 1.1 一句话定义

**国内开发者用的多模型API聚合网关，OpenAI兼容协议，按Token计费，支付宝/微信支付。**

### 1.2 目标用户

| 用户画像 | 占比 | 痛点 | 我们的解决方案 |
|---|---|---|---|
| **个人开发者（学生/独立）** | 60% | 用不起官方便宜，海外信用卡门槛 | ¥10起充，支付宝秒付 |
| **AI应用小团队（2-5人）** | 25% | 模型太多管理麻烦，账单混乱 | 一个Key管理所有模型，统一账单 |
| **企业研发团队（>5人）** | 10% | 需要发票/对公/合规 | 提供发票、专属客户经理 |
| **代购/分销代理** | 5% | 需要返佣系统 | 内置邀请返佣30% |

### 1.3 核心价值主张

1. **一个Key = 所有模型**：DeepSeek / Kimi / 智谱 / MiniMax / GPT / Claude / Gemini 全覆盖
2. **比官方便宜 30%-50%**：规模化采购 + 价格屠夫策略
3. **比同行稳定 99.9%**：5渠道冗余 + 智能切换
4. **5分钟接入**：改一行 base_url 即可，对 OpenAI SDK 完全兼容

## 2. 功能需求

### 2.1 MVP阶段（Day 1-7）核心功能

#### 模块A：API网关核心
- **A1. 多模型聚合**
  - 必须支持：DeepSeek V3、Kimi K2.5、智谱GLM-5、MiniMax M2.5、Azure OpenAI（GPT-5）
  - 选5家作为首发，Day 30扩展到10家
  - 渠道异常自动切换（故障切换）< 3秒
  
- **A3. 协议兼容**
  - 完全兼容 OpenAI ChatCompletion API（/v1/chat/completions）
  - 完全兼容 OpenAI Responses API（/v1/responses）
  - 支持 Anthropic Messages API（/v1/messages）
  - 支持流式输出（SSE）
  - 支持 Function Calling

- **A4. 计费引擎**
  - 按 Token 实时扣费（输入/输出分别计费）
  - 支持预付费（充值余额）和后付费（月结账单）
  - 用量实时统计 + 异常告警
  - 单用户 TPM/RPM 限速（防刷）

#### 模块B：用户控制台
- **B1. 用户系统**
  - 邮箱+密码注册（国内手机号验证备用）
  - 用户等级：普通用户 / 企业用户 / 渠道代理
  
- **B2. Token管理**
  - 用户可创建多个 API Key（最多10个）
  - 每个 Key 可独立设置额度、过期时间、模型白名单
  
- **B3. 用量统计**
  - 实时余额
  - 按模型/按日/按周/按月用量统计
  - 导出 CSV 账单
  
- **B4. 充值中心**
  - 微信支付 Native
  - 支付宝 当面付
  - USDT（海外客户）
  - 对公转账（大客户）

#### 模块C：企业站
- **C1. 落地页**
  - Hero区：一句话定位 + 立即试用按钮
  - 模型列表：5家×主流品种支持配置
  - 价格表：明码标价，比同行低
  - 接入教程：5分钟接入指南
  - FAQ：10个常见问题
  
- **C2. 控制台登录页**
  - 用户登录后跳到 new-api 后台

## 3. 非功能需求

### 3.1 性能指标

| 指标 | 目标 | 测量方式 |
|---|---|---|
| API可用性 | ≥ 99.5%（MVP阶段） | UptimeRobot监控 |
| 首字延迟（TTFT） | < 500ms（P95） | new-api日志 |
| 并发能力 | 100 QPS（Day 30） | 压测 |
| 故障切换时间 | < 3秒 | 手动测试 |

### 3.2 安全要求

| 项 | 要求 |
|---|---|
| 通信加密 | 全站HTTPS（Let's Encrypt） |
| API Key存储 | bcrypt哈希 |
| 用户密码 | bcrypt哈希 |
| 支付密钥 | 环境变量隔离存储 |
| DDoS防护 | Cloudflare免费版 |
| 风控规则 | 异常用量立即告警 |

### 3.3 运维要求

- 服务器：阿里云/腾讯云轻量，4核8G起步
- 备份：每日自动备份数据库
- 监控：UptimeRobot + new-api 内置日志
- 告警：飞书机器人告警（服务器宕机/余额不足/异常用量）

### 4.2 数据流（一次API调用）

```
1. 用户应用发起请求 → https://api.xxx.com/v1/chat/completions
2. Cloudflare → new-api 网关
3. 鉴权层：验证 API Key → 查用户余额 → 余额不足返回 402
4. 限流层：检查 TPM/RPM → 超限返回 429
5. 计费层：记录请求起始（用于按输出计费）
6. 路由层：根据 model 字段选渠道（DeepSeek/Kimi/GPT/...）
7. 转发到上游 API → 流式响应返回用户
8. 计费层：扣除实际 Token 用量（输入+输出分别计费）
9. 日志层：记录调用日志（用于用量统计+账单）
```

### 4.3 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 网关核心 | new-api（calciumion/new-api Docker 镜像，QuantumNous/new-api 仓库） | 节省90%开发时间，支持GPT-5/Claude Opus 4.6/Realtime API |
| 数据库 | SQLite（new-api默认）→ Day 30迁PostgreSQL | MVP够用，迁移成本低 |
| 缓存 | Redis | 用量统计、限流计数器 |
| 队列 | 不需要（MVP阶段） | 量级不到 |
| 日志 | 文件日志 + new-api内置 | 够用 |

## 5. 用户体验流程

### 5.1 新用户首次使用流程

```
访问首页 → 点击"立即试用"
   ↓
注册（邮箱 + 密码，10秒）
   ↓
免费获得 ¥5 测试额度（无需绑卡）
   ↓
进入控制台 → 创建 API Key
   ↓
复制 base_url + API Key → 替换到自己项目中
   ↓
5分钟接入完成 → 开始调用
   ↓
用完 ¥5 → 充值（¥10 起）
```

### 5.2 充值流程

```
控制台 → 充值中心
   ↓
选择金额（¥10 / ¥50 / ¥100 / ¥500 / 自定义）
   ↓
选择支付方式（微信 / 支付宝 / USDT / 对公）
   ↓
扫码支付 → 异步回调 → 余额更新
   ↓
收到飞书/微信通知
```

### 5.3 客服流程

```
用户遇到问题
   ↓
① 先看文档（90%问题能自助）
   ↓
② 加入客户群（飞书群+微信群）
   ↓
③ 群内 @客服（响应 < 30分钟）
   ↓
④ 仍未解决 → 一对一支持
```

| 风险 | 概率 | 措施 |
