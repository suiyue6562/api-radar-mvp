## 1. 产品定位

**一句话**：帮已经付费使用或准备付费使用大模型 API 的开发者和小团队，比较方案、看清费用、发现变化。

**不做什么**：
- 不做 API 中转（你的另一条业务线 `API中转站-MVP` 是）
- 不托管用户 API Key
- 不做新闻门户
- 一期不做用户评分社区（避免刷分破坏可信度）
- 一期不做企业采购询价（独立立项）

## 2. 用户与任务

### 2.1 首批用户（核心）

| 用户群 | 触发时刻 | 核心痛点 | 首版优先级 |
|---|---|---|---|
| **付费独立开发者**（Claude Code / Cursor / Cline 用户） | 第一次充值、当前渠道异常、续费前 | 兼容性、实际成本、少走配置弯路 | **P0** |
| **小团队技术负责人**（AI 应用团队） | 多人共用、上线前、增加用量 | 连续可用性、长任务表现、故障定位 | **P0** |
| 偶尔尝鲜找免费额度的人 | 新模型发布 | 找入口、领额度 | 服务但不验证付费 |
| 企业采购 | 合同采购 | 主体/合规/SLA | **后移**，不做 |

### 2.2 三大任务入口（首页组织）

| 入口 | 对应时刻 | 页面 | 主要交付 |
|---|---|---|---|
| **A. 准备充值，比较方案** | 购买前 | `/select` | 输入工具/模型/用量 → 输出 2-3 候选渠道对比 |
| **B. 当前不好用，检查问题** | 排障中 | `/check` | 选择当前渠道 → 看近期可用性、变化记录、是否需要切换 |
| **C. 关注的渠道，查看变化** | 持续使用 | `/watch` | 订阅渠道/模型 → 价格、上下线、故障事件时间线 |

### 2.3 JTBD（Jobs to be Done）

| 编号 | 任务 | 触发 | 完成标准 |
|---|---|---|---|
| JTBD-01 | 找出某模型有哪些可购买渠道 | 已确定模型 | 看到价格、条件、风险差异 |
| JTBD-02 | 估算月 API 成本 | 有大致调用量 | 分项成本+多方案对比 |
| JTBD-03 | 按场景选模型 | 尚未确定模型 | 可解释的候选清单 |
| JTBD-04 | 看某次变化是否影响自己 | 收到消息 | 看到变化前后、时间、来源 |
| JTBD-05 | 看当前渠道是否变差 | 使用中遇到问题 | 看到近期数据+是否需要切换 |

## 3. MVP 功能范围（10 周）

### 3.1 P0 模块

| 模块 | 内容 | 验收 |
|---|---|---|
| **首页 3 入口** | 选方案 / 查问题 / 看变化 | 用户 10 秒理解用途，1 跳进入 |
| **模型库** | 30 模型列表+详情+筛选 | 字段完整度 ≥ 70%（广覆盖版的妥协） |
| **渠道库** | 15 渠道列表+详情+筛选 | 含主体、支付、采购、数据政策 |
| **价格中心** | 标准化价格+比价+历史快照 | 输入/输出/缓存读写分列 |
| **计算器 v1** | 输入输出+缓存+套餐条件 | 1 亿 Token 月成本，最多 5 方案对比 |
| **API 行情** | 事件流+时间线 | 价格/能力/上下线/故障 |
| **渠道档案** | 主体/支付/退款/SLA/数据政策 | 来源可追溯 |
| **后台** | 录入/审核/发布/审计 | 价格变化必须留痕 |

### 3.2 P1（阶段 4 才做，本期不做）

- 实测报告（自有测试账户+合成任务）
- 稳定性监测（轻量请求+长任务两档）
- 价格提醒邮件
- 用户登录+收藏（先做邮箱验证码）
- 企业询价表单（**整模块砍掉**）

### 3.3 砍掉项

- ❌ 在线 API Playground（密钥责任）
- ❌ "全网最低价"宣传
- ❌ 单项星级总评分
- ❌ 用户评分社区
- ❌ 自动抓取直接发布（必须经审核）
- ❌ 用户充值/余额系统

## 4. 渠道与模型首发范围

| 维度 | V1.1 目标 | 字段完整度要求 |
|---|---|---|
| 模型厂商 | 10 家 | 8 家达标 |
| 模型 | 30 个 | 20 个字段完整 |
| API 渠道 | 15 家 | 8 家达标 |
| 渠道×模型组合 | 100+ 条 | 60 条字段完整 |
| 行情事件 | 回填 90 天 | 50 条 |
| 场景标签 | 8 个 | 编程/客服/翻译/写作/推理/多模态/图像/语音 |

**取舍逻辑**：广覆盖意味着每条记录的字段完整度只能保证 70%。这是权衡——后续阶段会回头补深。

## 5. 风险可见性（不做总星级）

每个渠道详情页**必须三栏分列**：

| 栏位 | 内容 | 来源 |
|---|---|---|
| **技术表现** | 可用率、首 Token 延迟、错误率（P1 数据先标"待补充"） | 自有测试（P1 后才有）+ 第三方转引 |
| **商业条件** | 支付、发票、合同、SLA、最低充值、退款 | 服务商声明 + 来源链接 |
| **政策证据** | 数据区域、日志保留、是否用于训练、地区限制 | 服务商政策页 + 日期 |

**禁止**：用"5 星 / 4.5 星"等单一评分替代三栏。

## 6. 北极星与指标

### 6.1 北极星

**月度完成有效决策动作的用户数**。

有效决策动作定义（比 V1.0 更严格）：
- 完成多方案比价
- 完成成本计算并查看结果
- 收藏 + 30 天内回访
- 出站点击渠道
- **新增**：填"我根据这个结果做了什么"回访（30 天后弹窗）

仅浏览页面不算。

### 6.2 MVP 指标（90 天）

| 指标 | 目标 |
|---|---|
| 主流模型价格字段完整率 | ≥ 70%（广覆盖版的妥协） |
| 公开价格 7 天内验证比例 | ≥ 85%（广覆盖压力下调） |
| 搜索到有效决策转化率 | ≥ 12%（广覆盖质量下，调低） |
| 计算器完成率 | ≥ 55% |
| 30 天回访率 | ≥ 12% |
| 渠道详情到出站点击率 | ≥ 6% |

## 9. 路线图

| 阶段 | 验证问题 |
|---|---|
| **MVP（W1-W10）** | 用户是否需要结构化 API 决策工具 |
| 阶段 2（W11-W16） | 用户是否愿意持续回访依赖数据（实测+提醒） |
| 阶段 3（W17-W24） | 能否产生高质量交易线索（**企业询价进入此处独立立项**） |
| 阶段 4（W25+） | 数据是否具备订阅价值（付费会员、数据 API） |
| 阶段 5（远期） | 统一 API Gateway（独立业务，与你的 `API中转站-MVP` 合并评估） |
