## 1. 市场验证：需求是真实的

### 1.1 OpenAI对中国API封锁 → 催生整个中转行业

2024年7月9日起，OpenAI开始阻止来自非支持国家（包括中国大陆）的API流量。这意味着所有国内AI开发者、API公司、AI应用团队都**被迫**找中转服务。

直接证据：
- CloseAI（closeai-asia.com）2022年开始做，2023年3月首批商用OpenAI代理，**客户名单**：阿里、腾讯、百度、清华、北大
- 词元无忧API（token5u API）：2026年市场份额前列
- Jeniya Chat、API2D、147API、PoloAPI、Nio API、AzAPI——整个赛道至少有10+成熟玩家

**结论**：需求已经被验证为**真实刚需**，不是想象。

### 1.2 市场规模：可估算到亿级

按以下逻辑估算：
- 中国AI开发者约200-500万（按GitHub/CSDN/掘金活跃用户估算）
- 其中**有API调用需求**的占30%-50% = 60-250万人
- 中转服务渗透率5%（保守）= 3-12万付费用户
- ARPU ¥500/月（中位数）= 月市场规模 ¥1,500万-6,000万
- 年市场规模 **¥1.8亿-7.2亿**

**结论**：赛道够大，容得下5-10家中型企业，我们的份额目标1%-3% = 年营收¥180万-2,160万。

### 1.3 竞争格局：头部集中，但长尾分散

| 玩家 | 优势 | 我们的机会 |
|---|---|---|
| CloseAI | 规模大、企业客户多 | 价格更便宜 + 服务更敏捷 |
| 词元无忧API | 生态完善 | 个人/中小开发者渠道空白 |
| new-api（calciumion/new-api，活跃社区继任者） | 部署简单，支持GPT-5/Claude Opus 4.6/Realtime API | 我们是运营服务，不是技术工具 |
| Jeniya Chat | 体验好 | 客服响应、稳定性是壁垒 |

**结论**：没有绝对垄断，玩家多但**没有任何一家**做到"中小企业最信任、文档最清晰、价格最优、客服最快"的4项全能。**这就是我们的差异化空间**。

## 3. 技术可行性：现成方案，不需要发明轮子

### 3.1 技术栈（用现成开源，不自研）

| 组件 | 选型 | 理由 |
|---|---|---|
| API网关核心 | **calciumion/new-api:latest**（QuantumNous/new-api 官方镜像） | 开箱即用，模型聚合、计费、分销、登录全栈 |
| 部署方式 | Docker Compose | 一个人30分钟部署上线 |
| 渠道扩展 | new-api 支持30+模型渠道 | 文档清晰，新模型接入<1小时 |
| 前端 | new-api自带 | 用户控制台、Token管理、用量统计都现成 |
| 支付 | 微信支付Native + 支付宝当面付 | 个人开发者也能开 |
| 客服 | 飞书群 + 微信群 | 0成本 |
| 监控 | UptimeRobot（免费）+ new-api 内置日志 | 够用 |

### 3.2 部署架构

```
[用户浏览器] ──HTTPS──> [new-api 前端]
[用户API调用] ──HTTPS──> [new-api 网关]
                          ├─> DeepSeek API（国产）
                          ├─> 智谱GLM API（国产）
                          ├─> MiniMax API（国产）
                          ├─> Kimi API（国产）
                          ├─> Azure OpenAI（合规路线）
                          ├─> Anthropic Claude
                          └─> Google Gemini
```

**所有上游只对 new-api 域名白名单，**用户只看到我们的域名，**任何一家上游挂了秒切**。

### 3.3 关键技术风险与应对

| 风险 | 应对 |
|---|---|
| 上游封号 | 多渠道冗余（同一模型至少3家供应商） |
| 节点不稳定 | 香港+东京+新加坡三节点，DNS智能解析 |
| DDoS | Cloudflare免费版+限流 |
| Token被盗刷 | 用量监控+异常告警+单用户TPM限速 |

## 5. 合规可行性：路径清晰

### 5.1 我们做的是什么

**法律定位**：**AI模型API聚合与加速服务**（属"增值电信业务-信息服务"范畴）

**明确不做**：
- ❌ 直接面向C端用户提供AI对话生成内容
- ❌ 训练/微调模型
- ❌ 处理个人敏感信息（只处理用户API Key和用量数据）

### 5.2 需要办的手续

| 手续 | 必要性 | 难度 | 时间 |
|---|---|---|---|
| ICP备案 | 必需 | 低 | 7-10天 |
| 微信支付商户号 | 必需 | 低 | 1-3天 |
| 支付宝当面付 | 必需 | 低 | 1天 |
| 增值电信业务许可证（ICP经营许可证） | 视规模 | 中 | 30-60天（Day 60后启动） |
| AI应用登记 | **非必需**（我们不做应用层，只卖API） | - | - |

**关键**：**我们不直接给C端用户提供AI对话生成内容**——我们给的是"API Key + 计费系统"，是开发者工具，**不属于"生成式AI应用"**，不在《生成式人工智能服务管理暂行办法》的备案/登记范围内。

### 5.3 风险红线

- ❌ 不要在产品名/宣传中提"AI聊天"、"ChatGPT中国版"、"对话机器人"等
- ✅ 只强调"开发者API聚合"、"模型加速"、"成本优化"
- ✅ 用户协议明确：服务对象是开发者，不是终端消费者
